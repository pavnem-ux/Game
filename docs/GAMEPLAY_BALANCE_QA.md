Продолжение Task 07 / PR #3 по решению владельца. Архитектура Core, Enemy AI, навыков,
единого планировщика и правила выбора не заменены. Все новые параметры баланса предварительные.

Скорость игрока, урон/рисунок/скорость меча, остальные стартовые эффекты, формулы статусов,
Resistance/Dodge, защита после попадания, воскрешение, кулдауны навыков, слоты 4/6 и правила
выбора сохранены. Bleed кинжалов Разбойника остаётся. Slow умножает новую скорость врагов,
Stun по-прежнему запрещает движение/новые атаки; готовые снаряды не меняются.

Нормальные спавны распределяются детерминированно без новых RNG-бросков: при постоянном share
число ranged после N успешных спавнов равно `floor(N * share)`. При 18% начальные 12 врагов
содержат 2 ranged, каждые 100 спавнов — 18. Счётчик общий для начальной группы и подкреплений,
сохраняется при паузе и Revive. Активный cap 120, лимиты/расписание волн и размещение за камерой
не менялись. Явная DEV-группа остаётся тестовой смесью с каждым третьим ranged.

## HP и лечение

`GameplayWorld.progression` раскрывает `run-level-up` в отдельные уровни. Каждый сразу лечит
на 15% текущего Max HP через `core.heal`; HP ограничен Max HP, дроби сохраняются. Выборы карт
ставятся в очередь после лечения всех полученных уровней. Выбор карты/переброс не повторяют
лечение. XP без уровня и получение урона не лечат. Постоянный уровень не меняется.

На каждый уровень публикуется `RunLevelHealingEvent` в канале `progression`:
`{ type: 'run-level-healed', level, requestedHealing, healed }`. Он существует и при полном HP
(`healed: 0`). Core публикует своё обычное `healing` только при положительном восстановлении;
при полном HP мир сохраняет прежнюю сущность без пустой записи HP. Мёртвый игрок не оживает.

HUD округляет текущий и максимальный HP через `displayHp`; отображаемый текущий HP ограничен
отображаемым максимумом. Подпись и aria-значения целые, геометрия полоски использует исходную
точность. Значения Core, урон и лечение не округляются. QA-ввод и JSON могут показывать точные
дроби для диагностики.

## Обзор навыков

Кнопка **Навыки** открывает немодальную панель: имена, иконки, описания, текущий ранг I–V,
эффект ранга, автоматические/пассивные категории, занятые/свободные слоты и кулдауны. Классовая
пассивка входит в общий лимит 6. Показано число оставшихся перебросов; в диалоге уровня оно
по-прежнему видно на кнопке переброса.

Панель не отправляет pause/resume-команд, не останавливает симуляцию и не отменяет ручную паузу,
выбор навыка или revival. На телефоне ограничена ширина/высота и есть прокрутка. Кнопки доступны
с клавиатуры. Окно выбора уровня, слоты, предложения и ранги остаются прежними.

## Production и QA Preview

Это две **разные сборки и директории**:

| Цель                   | Build command      | Артефакт   | Deploy / Preview command                          |
| ---------------------- | ------------------ | ---------- | ------------------------------------------------- |
| Production `main`      | `npm run build`    | `dist/`    | `npx wrangler deploy`                             |
| Обычный Preview без QA | `npm run build`    | `dist/`    | `npx wrangler preview`                            |
| Явный QA Preview       | `npm run build:qa` | `dist-qa/` | `npx wrangler preview --config wrangler.qa.jsonc` |

`wrangler.jsonc` не изменён. QA-конфигурация отдельная и не используется для production.
**Никогда не запускать `wrangler deploy --config wrangler.qa.jsonc` для Worker `game`.**

Политика в `config/qa-build.mjs` устанавливает compile-time `__QA_BUILD__`:

- обычный `npm run build` всегда задаёт `false`, независимо от `?debug`, `?qa` и переменных
  `VITE_*`; тестовые чанки и глобальные объекты удаляются из production;
- только явный `vite build --mode qa` включает QA, если Workers Builds передал `WORKERS_CI=1`
  и непустой `WORKERS_CI_BRANCH`, отличный от `main`;
- `main` запрещён также по сигналам GitHub Actions (`GITHUB_REF`, `GITHUB_REF_NAME`,
  `GITHUB_HEAD_REF`); противоречивые сигналы закрывают сборку;
- на CI отсутствие метаданных ветки завершает QA build ошибкой;
- только для локальной проверки вне CI разрешён явный `GAME_LOCAL_QA=1 npm run build:qa`.

`?debug` лишь открывает уже разрешённую при сборке QA-функциональность. Он не является границей
безопасности. Legacy-прототип остаётся DEV-only даже в QA-сборке. Клиент не получает токены,
секреты или облачные привилегии; QA даёт только инструменты текущего локального забега.

### Настройка владельцем в Cloudflare

1. Открыть **Workers & Pages → game → Settings → Builds**. Репозиторий остаётся приватным.
2. Сохранить Production: ветка `main`, build `npm run build`, deploy `npx wrangler deploy`.
   Ни build, ни deploy production не менять.
3. В **Previews Base**, только для Preview-веток, установить build **`npm run build:qa`**,
   Preview command **`npx wrangler preview --config wrangler.qa.jsonc`**. Root — корень репозитория.
4. Не добавлять и не переопределять `WORKERS_CI`, `WORKERS_CI_BRANCH` или секреты: это системные
   метаданные Workers Builds. Не задавать `NODE_ENV=development` для размещённой сборки.
5. Пересобрать текущую ветку PR #3. В логе должны появиться `dist-qa/` и успешная команда Preview.
6. Взять **реальный** URL из deployment/Preview в дашборде или комментария Cloudflare в PR.
   Документированный шаблон branch Preview:
   `https://<preview-name>-game.<account-subdomain>.workers.dev/?debug`.
   Для конкретного deployment: `https://<deployment-id>-game.<account-subdomain>.workers.dev/?debug`.
   Имя Preview назначает Cloudflare; нельзя угадать URL по имени ветки со слешами.
7. Открыть этот URL, проверить метку **QA PREVIEW**, нажать **QA · Тестирование**. Production URL
   с `?debug` обязан по-прежнему показывать обычную игру без QA/DEV.

Если интерфейс/план Cloudflare не позволяет надёжно разделить команды Production и Previews Base,
не менять production и не включать QA в обычный build. Создать отдельный Worker **`game-qa`**, связать
с этой feature-веткой приватного репозитория, build `npm run build:qa`, deploy
`npx wrangler deploy --config wrangler.qa.jsonc --name game-qa`. Его build-ветка должна быть
не `main`; политика всё равно запрещает main. Это отдельное QA-размещение, не production `game`.

Preview URL по умолчанию публичный; при необходимости ограничить доступ к QA через Cloudflare
Access. Приватность GitHub сама по себе не закрывает опубликованный Preview.

### QA-инструменты

Панель сохраняет HP/защиту/смерть/Revive, спавны, статусы и журнал. Есть выдача XP и кнопка
«Следующий уровень забега», выдача навыка конкретного ранга, список приобретённых навыков
с кнопкой улучшения, слоты и перебросы. Выдача по-прежнему проверяет класс/слоты/ранги через
существующий RunSkills. Для контроля синергий выдавать нужные навыки по таблице
[IN_RUN_SKILLS.md](IN_RUN_SKILLS.md), применять статусы и смотреть события `synergy-triggered`.

## Автоматические проверки

```bash
npm ci
npm run typecheck
npm run format:check
npm test
npm run build
npm run test:production
# В другой вкладке терминала запустить npm run dev:
npm run test:e2e
# Локально, вне CI:
GAME_LOCAL_QA=1 npm run build:qa
npm run test:qa
```

GitHub Actions сохраняет три прежние job и добавляет отдельную QA build/browser job на PR.
Новая job не имеет write permissions/секретов и не публикует сайт. Policy-тесты проверяют
обычную production-сборку, запрет main, отсутствие метаданных и явный локальный opt-in.
Production regression сканирует JS на QA/DEV-код и проверяет отсутствие контролов/глобальных
объектов даже с query-параметрами. QA regression проверяет готовый статический QA-артефакт,
кнопки панели, XP/лечение, выдачу/улучшение, обзор навыков/кулдауны, whole HP, мобильный layout
и сохранение ручной паузы. Unit-тесты проверяют движение/Slow/Stun, точные cooldown deadlines,
распределение спавнов, уровни/кристаллы/лечение и все 12 условий синергий.

## Ручной QA checklist владельца

- [ ] В Production `/?debug` и `/?debug&qa=true` нет DEV/QA; обычный забег работает.
- [ ] В реальном QA Preview `/?debug` видны QA PREVIEW и панель, в консоли нет ошибок.
- [ ] За все четыре класса маневрировать между melee/ranged: враги медленнее, пауза между атаками
      больше; скорость героя и его оружия прежняя. Slow/Stun работают.
- [ ] Установить низкий HP, выдать ровно XP до следующего уровня: восстановление 15% Max HP,
      затем выбор карты. Повторить с несколькими уровнями, почти полным HP и XP без уровня.
      Получение урона само не лечит. Подпись HP всегда целая и не выше максимума.
- [ ] Выдать 4 авто и 6 пассивных (включая классовую), проверить имена, ранги, описания,
      свободные слоты, кулдауны, недоступность пятого авто/седьмого пассивного и ранг выше V.
- [ ] Открыть обзор во время движения/атак: мир продолжает работать. Пауза, выбор и Revive
      не отменяются панелью. Перебросы видны в окне уровня.
- [ ] Без приобретённых навыков стартовые DoT не открывают синергии. Выдать подходящий навык:
      правила из таблицы работают одновременно; посторонняя общая пассивка не открывает их.
- [ ] Меч Воина наносит прямой урон без Bleed; кинжалы Разбойника накладывают Bleed.
- [ ] Дождаться нескольких волн: ranged присутствуют, но большинство — melee; пауза/Revive
      сохраняют расписание и лимиты.
- [ ] На телефоне открыть/прокрутить обзор, выбрать навык, закрыть панели и проверить джойстик.

Реальные CI/Cloudflare статусы и размещённый URL проверяются отдельно: локальный зелёный build
не доказывает, что настройки дашборда уже применены или сайт опубликован. Известный ранее
интермиттирующий E2E сбой автоматической паузы отслеживать отдельно при повторении; не ослаблять
его assertion. Длинные 15–20-минутные забеги и физический телефон требуют ручной проверки.
