# Fantasy Survivors: архитектура и план

## Требования и границы

Браузерный top-down survivor с оригинальным оформлением. Итоговая цель: четыре класса, перманентная экипировка в семи слотах и пяти редкостях, ранговые таланты с зависимостями, временные навыки и постоянные питомцы. Полный набор не входит в первый этап.

Milestone 1: один маг, один враг, автоматические магические снаряды; WASD/стрелки, урон, смерть, опыт, выбор из трёх случайных улучшений и рестарт. Победа по таймеру не вводится: забег заканчивается при 0 HP. Направление баланса — 15–20 минут; реальные длительности потребуют игровых сессий. Аккаунт, сеть и сервер не нужны.

## Модули

- `config`: типизированные данные баланса, стартовый класс, оружие, враг, улучшения. Будущие классы и предметы добавляются в каталоги.
- `core`: контракты, мост команд/снимков между UI и движком, чистая логика опыта, улучшений и боевого урона.
- `engine`: Phaser Scene координирует движение, спавн, бой, опыт и отрисовку. Отдельные системы владеют своими сущностями и жизненным циклом.
- `ui`: React отвечает за меню, HUD, выбор улучшений, паузу и итог. Симуляция не зависит от состояния React.
- `progression`: хранилище localStorage с версией схемы и валидацией. Сейчас только рекорд; будущая миграция будет расширять сохранение.
- `tests`: числовые инварианты и браузерный сценарий реального забега.

Команды UI идут в типизированный мост; неизменяемые снимки HUD публикуются до 10 раз/с, не каждый кадр. Позиции и массивы врагов не попадают в React. Phaser владеет Canvas и обработчиками ввода; React уничтожает экземпляр движка при unmount.

## Играбельные этапы

1. **Арена** (текущий): полный минимальный цикл; сборка, строгий TypeScript, функциональная проверка браузером.
2. **Классы и навыки**: четыре конфигурации, формулы роста, активные/пассивные эффекты, уровни, cooldown, AoE/DoT/контроль. Проверка каждого класса в забеге.
3. **Лут и экипировка**: семь слотов, редкости, инвентарь, inspect/equip/unequip, сохранение и миграции.
4. **Таланты**: ранги, зависимости, очки и деревья по классам; отдельно от временных улучшений.
5. **Спутник**: следование, атака, выбор, уровни и постоянный опыт питомца.
6. **Контент и баланс**: биомы, дополнительные враги, оружие, настройки, звук, 15–20-минутные сессии и профилирование.
   Каждый этап требует отдельного согласования. Milestone 2 не начинается автоматически.

## Риски и решения

- Нагрузка: лимиты сущностей; повторное использование снарядов/врагов/кристаллов; квадрат расстояния для большинства проверок. На текущем лимите допустим перебор врагов; позже spatial hash для тысяч объектов.
- GC: сущности хранятся в постоянных пулах; в update не создаются новые Phaser-объекты. Графика рисуется одним батчем. Снимки UI создаются с ограниченной частотой.
- Canvas выбран для предсказуемости на headless/слабых GPU; процедурные формы дают читабельность без сторонних ассетов. В будущем можно заменить renderer и текстуры независимо от симуляции.
- Пауза: игровое время и cooldown не зависят от реального времени вкладки. Потеря видимости ставит забег на паузу; dt ограничен для защиты от скачков.
- Сохранения могут быть повреждены или недоступны: безопасный fallback; версия схемы не перезаписывается при обнаружении неизвестного будущего формата.
- Боевой баланс пока предварительный: отсутствие теста на 20 минут не считается подтверждением балансировки.
- Полноценное mobile UX не является требованием первого этапа; меню адаптивны, добавлен базовый экранный джойстик.
