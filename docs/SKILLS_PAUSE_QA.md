## Навыки при паузе и выборе уровня

«Навыки» есть в обычном HUD, в окне ручной паузы и в диалоге уровня. В обычном режиме это
немодальный обзор без автоматической паузы. При ручной паузе/выборе обзор открывается над
существующим диалогом; underlying диалог получает `inert` / `aria-hidden`, но не удаляется.
Его карты, offer ID, очередь и перебросы не меняются. «Назад» / «К выбору» / Esc возвращают
туда же. Никаких команд resume, выбора карты или расходования переброса обзор не отправляет.

Клавиатурный обработчик обзора в capture-фазе перехватывает Esc и, в уже paused/level-up режиме, P до Phaser: Esc закрывает
обзор, P не возобновляет игру под ним. Во время обычной игры P по-прежнему ставит мир на
ручную паузу, в том числе при открытом обзоре. В модальном режиме Tab удерживает фокус на кнопке
возврата; после закрытия фокус возвращается на открывшую кнопку. Обработчик удаляется вместе
с панелью. На новом забеге UI-состояние обзора сбрасывается.

Автоматические и пассивные навыки разделены цветом/секциями, показаны имена, иконки, ранги I–V,
описания, эффект ранга, кулдауны и перебросы. Есть явные пунктирные пустые слоты; классовая
пассивка по-прежнему занимает один из шести пассивных. Desktop использует две колонки,
телефон — одну с прокруткой. Поверх frozen-диалога обзор может занять большую высоту; во время
обычной игры остаётся компактным, сохраняя место для управления.

## Stun

Вместо маленькой точки над оглушённым врагом — контрастный золотой бейдж **СТАН** с тёмным
фоном и короткой линией. Синий Slow остаётся у ног, подписи DoT расположены отдельно.
`stunIndicator` читает только авторитетный `EnemySnapshot.control.stunned` и `alive`; отдельного
визуального таймера нет. Бейдж скрывается в первом кадре после окончания Stun/смерти/ухода в меню.
Пауза сохраняет его, потому что сама длительность Stun заморожена.

Text-объекты переиспользуются: максимум — пиковое число оглушённых врагов (ограничено enemy cap).
Текст/стили задаются при создании, каждый кадр меняются только позиция и видимость. Частиц нет.
В QA bridge `presentation().stunIndicators` отражает реальные видимые Text-объекты для регрессии;
в Production самого bridge нет.

## QA-инструменты

Те же build policy / Preview commands из [GAMEPLAY_BALANCE_QA.md](GAMEPLAY_BALANCE_QA.md).
Production `wrangler.jsonc`, настройки Cloudflare, баланс и зависимости не менялись.

### Synergy Diagnostics

QA-панель показывает ровно три синергии текущего класса: русское/английское имя, ID, требуемые
теги приобретённого навыка, locked/unlocked, число активаций и последнее simulation time / target.
«Ещё не срабатывала» отличает ноль от активации в момент 0.00 с. Для Воина показаны
Battle Momentum, Skull Crusher и Seismic Impact.

Условия владения читаются через чистый `SynergyResolver.isEligible(id)`: это прежняя проверка
без изменения формулы. Счётчики обновляются синхронно только на фактически опубликованном
`synergy-triggered`, до потери старых записей из bounded history. Анимации и наличие Stun ничего
не прибавляют. Память ограничена тремя записями. «Сбросить счётчики синергий» / QA-команда
`reset-synergy-counters` очищают только счётчики и последнее событие; мир, RNG, acquired skills,
God Mode и proc-кулдауны сохраняются. Новый забег начинает новую диагностику.

### God Mode

Переключатель **God Mode ON/OFF** / QA-команда `{ type: 'god-mode', enabled: boolean }`
по умолчанию OFF в каждом новом забеге. ON блокирует только потерю HP игрока от прямого и
периодического урона. OFF снимает guard немедленно. Статы, Max HP, Resistance и Dodge не меняются.

Порядок остаётся прежним: Core проверяет входы, делает обычные crit/Dodge/Resistance расчёты,
расходует барьер, затем перед записью HP QA-only Core возвращает прежний HP игрока. Результат
содержит нормальный рассчитанный `damage`, но `appliedDamage: 0`, без вымышленных damage/death
событий. Игрок может наносить урон и убивать, вражеские попытки/снаряды, таймеры, волны, XP,
статусы и синергии работают. Обычные правила паузы/выбора/revival сохраняются.

QA-адаптер разрешает on-hit статусы успешного ненулевого входящего удара даже при предотвращённой
God Mode потере HP. Он не обходит Dodge, смерть цели или обычную политику применения статусов.
Тики статусов продолжаются. Это отличается от прежней «тестовой защиты», которая блокирует
ещё и применение эффектов. Обе опции остаются разными; для проверки статусов с God Mode старую
защиту выключить. Сам God Mode не выдаёт full-invulnerability и не восстанавливает умершего.

Явные QA-команды установки HP / контролируемой смерти намеренно продолжают работать: guard
приостанавливается только на их синхронное выполнение и восстанавливается в `finally`.
Это инструменты владельца, а не входящий урон симуляции.

## Изоляция и совместимость

`src/gameplay/qa.ts` загружается исключительно через существующий динамический testing import,
за `import.meta.env.DEV || __QA_BUILD__` и `?debug`. Обычная Production-сборка удаляет QA-классы,
команды, контролы, диагностику и глобальные объекты. `?debug` сам по себе не включает их.
Авторизованный QA Preview и local dev создают `QaGameplayWorld`; быстрый первый клик ждёт
готовности QA-фабрики, поэтому забег не теряет поддержку guard из-за загрузочной гонки.

Минимальные аддитивные точки расширения без новых формул/значений:

- `CombatCore.hpAfterDamage` — protected hook после mitigation/барьера; default — прежнее
  `max(0, currentHp - unabsorbedDamage)`. Единственная запись HP остаётся в Core.
- `WeaponStatusAdapter.hasHpLoss` — protected eligibility hook; default — прежнее
  `appliedDamage > 0`. Вся остальная валидация/проверка живой цели остаётся общей.
- Второй необязательный аргумент `GameplayWorld` — фабрика Core. Protected `createStatusAdapter`
  и `record` позволяют QA-подклассу наблюдать реальные события и подставить адаптер. Старые
  конструкторы/API работают как раньше. QA OFF детерминированно совпадает с обычным миром.
- `AlphaState.qa` — необязательный immutable QA snapshot, отсутствующий в Production.

В production остаются только общие точки расширения с прежним поведением, без God Mode guard
или пути его включения. Production regression сканирует все JS на имена QA-команд/реализаций
и проверяет отсутствие контролов/глобальных объектов. Build policy Task 07.1 не ослаблена.

## Проверки и ручной checklist

Автоматизация: unit-тесты direct/DoT/projectiles/Dodge/барьера, God ON/OFF/new run, unchanged
stats/normal-world equivalence, все классы/prerequisites/счётчики/time zero/reset/overflow history,
Stun до/на expiry/при паузе; QA browser — Skills при паузе и очереди из трёх уровней на desktop
и телефоне, неизменность мира/карт/перебросов, Esc/P, поля/пустые слоты, реальные Stun Text-объекты,
God Mode, диагностика/reset. Все предыдущие assertions сохранены; сценарии теперь явно
возвращаются из Skills перед взаимодействием с underlying диалогом.

Выполнить `npm run typecheck`, `npm run format:check`, `npm test`, `npm run build`,
`npm run test:production`, non-main `npm run build:qa`, `npm run test:qa`, `npm run test:e2e`.

Владелец проверяет реальный QA Preview `/?debug`:

- [ ] Начать любой класс, открыть Skills во время игры: мир работает. Включить ручную паузу,
      открыть Skills, нажать Esc/«Назад»: пауза сохраняется, Continue доступен.
- [ ] Выдать XP сразу на несколько уровней. В окне выбора открыть Skills и вернуться: те же
      карты, очередь, rerolls; таймер/враги/кулдауны стояли. Выборы работают после возврата.
- [ ] Сверить 4/6 слотов, ранг, описания и свободные места, прокрутку и клавиатуру на телефоне.
- [ ] Воином приобрести Ground Slam / Shield Bash: золотой СТАН заметен над врагами и сразу
      исчезает после эффекта; Slow/DoT не показывают СТАН.
- [ ] В QA проверить 3 синергии класса: без навыка locked; с нужным навыком unlocked. Фактические
      события увеличивают счётчик. Reset не начинает новый забег и не меняет proc cooldown.
- [ ] При выключенной старой тестовой защите включить God Mode: contact/projectiles/DoT не
      уменьшают HP, статусы и атаки продолжаются. OFF возвращает урон. Новый забег — OFF.
- [ ] Production `/?debug&qa=true` не показывает God Mode/QA, globals отсутствуют.

Отдельное независимое ревью и owner approval нужны до merge. Реальный Cloudflare Preview,
физический телефон и долгое ручное тестирование проверяются отдельно. Упомянутый ранее crash
не исследовался: это явно вне Task 07.2. Известный intermittent pause E2E фиксировать отдельно
при повторении; тест не ослаблять.
